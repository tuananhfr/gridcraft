# ERPCons changes

- (desktop) The window opens maximized, and Restore gives a window that fits the screen, centred above the taskbar (at most 1440×900). The fixed 1440×900 start size ran off 1366×768 screens and 150 % scaling, losing the close button under the screen edge and the bottom under the taskbar; eframe only clamps it to the whole monitor (`apps/gridcraft/src/window_fit.rs`).
- (desktop, Windows, 2026-10-30) Windows releases no longer ship `gridcraft-cli`: the MSI and the portable zip contain `gridcraft.exe` alone, because `gridcraft-cli run --cmd … --out` and `mcp` edit workbooks without the PI licence gate the app now enforces (owner decision, as pdfcraft and UbotCAD did). `packaging/windows/package.ps1` builds only `-p gridcraft`, checks, copies and signs only the app and no longer smoke-tests the CLI; `gridcraft.wxs` drops the `GridcraftCli` component, so the major upgrade removes the copy earlier MSIs installed; `test-desktop-shortcut.ps1` builds only the app fixture and asserts the CLI is not installed; `docs/releasing.md` says so. `erpcons-office`'s `build/desktop-win.sh` stops cross-building it. The crate stays in the workspace (tests, `cargo xtask` gates, development and agents). macOS, Linux, Flatpak and FreeBSD packaging still include it; they are not released by ERPCons. `.github/workflows/windows-arm64.yml` is unchanged: its upstream reusable workflow (`craft-common-actions`) still expects `gridcraft-cli.exe` in the installed MSI and fails without it, as for pdfcraft; ERPCons releases do not go through it.
- (desktop, 2026-10-30) Editing needs a PI licence (erpcons-account and pi-mock v0.5.0, ADR 0013): with `ERPCONS_PI_ISSUER` set at build time the account turns `Config::offline_licensing` on, and the four Office apps share one device and one `erpconsoffice` lease. Opening, viewing, Save, Save As, Export, Print and Copy always work; every edit is locked until this device holds an active lease granting `erpconsoffice.use` (`OFFICE_USE`) and `allowed(OFFICE_USE)` agrees. The lock reuses the read-only state of the web view mode: `DocAccess::edit_lock` (engine) is set on every open document and on those opened later by `Session::set_edit_lock`, refuses what a read-only document refuses except Save (edits made before the lock are never lost), and its reason is the notice of a refused edit; the ribbon greys as for a read-only document. A cell, formula-bar or text-box edit in progress when the lock arrives is entered first; a new lease unlocks the open workbooks without reopening them (`crates/ui-egui/src/edit_lock.rs`, `SheetApp::set_edit_lock`, read from `AccountHook::edit_lock` every frame from cached state only). Reasons (`apps/gridcraft/src/account/licence.rs`, the order of cadcraft's `denial_in`): signed out "Sign in with PI ID to edit" / "Đăng nhập PI ID để sửa"; personal context "Choose an organization to edit" / "Chọn tổ chức để sửa"; device revoked, device limit, no plan (`NotEntitled`, or a lease without `use`), not activated, no credential store, lease expired offline ("Connect to the internet to renew your license and edit") or online ("Could not renew your license; the app keeps trying"); the account still opening, and an account that cannot open, keep editing locked too. File › Account shows the reason (guests: instead of "Signing in is optional…", above the Sign in button; signed in: an "Editing" / "Chỉnh sửa" row) with Retry where it can help; Retry syncs, then retries a device-cap or not-entitled activation (`Account::retry_activation`). A refused edit that a sync may lift asks the account thread for one, at most once a minute and backing off to an hour while it stays (`account/resync.rs`, as cadcraft 1da7855). Feature ids follow ADR 0013 (`erpconsoffice.view|export|use`); `is_pro_feature` now counts `use`, and the new `is_paid_feature` (without `use`) keeps the web's licence line and `allowed` fallback as before. Debug builds may pin pi-mock's lease key with `ERPCONS_PI_DEV_LEASE_KEY=kid:hex` at build time; a release build fails to compile without pinned `PLATFORM_KEYS`. Web unchanged: its hook asks for no lock. Without `ERPCONS_PI_ISSUER` there is still no account and no lock. Tests: engine `doc_access` (+2), ui-egui `tests/edit_lock.rs` (4, kittest; `GRIDCRAFT_ACCOUNT_SCREENSHOTS` saves renders), `gridcraft` bin against pi-mock (`account::licence_tests`: guest locked with Save/Save As/Export/Print/Open kept, free-plan sign-in unlocks the open workbook, the free plan's lease two days from expiry reads Free with no warning, revoked device, lease expired online then offline, personal context, Retry after `NotEntitled`, refused edit resyncs, account that cannot open; plus `licence`, `resync`, `config` unit tests). The free plan reads as the free plan, as in wordcraft and pdfcraft: its lease, which grants only `use` beyond `view`/`export` and renews itself while online, maps to `LicenceView::Active { pro: false }` through `is_paid_feature` (`apps/gridcraft/src/account.rs`), so File › Account reads "Free · offline until {date}" / "Miễn phí · dùng ngoại tuyến đến {date}" and the 7/3/1-day renewal warning is not shown; a lease granting a paid feature still reads "Valid until {date}" and gets the warning. The edit lock is unchanged (`licence.rs` still asks for `use`). Local gate (`erpcons-office/build/run.sh gate`, log `gate-pireal-gridcraft-20261030T100048Z-test.log`): rustfmt, workspace clippy, wasm32 clippy passed; workspace tests passed=2325 failed=0; `cargo check --release -p gridcraft` passed (run before the free-plan change, log `gate-pireal-gridcraft-20261030T082943Z-test.log`).

- (web) `window.erpHost` v2 access modes (`erpcons-office` `docs/erp-host.md`, rules 12–15): version 1 or 2 is accepted, and with 1 nothing below applies. `open(doc)` reads `mode` (`edit`, `comment`, `view`; absent is `edit`, an unknown value is read as `view`; `comment` is `view` for the content until comments come to the web, refusing with its own notice "Commenting on the web is coming later; for now this document is view-only." / "Nhận xét trên web sẽ có sau, hiện chỉ xem được" (`DocAccess::commenter`)), `canDownload` (only `false` turns it off) and `preserveView`; `setMode(docId, mode, canDownload)` changes an open document's access in place, keeping the workbook and its undo history, and a downgrade first commits text still held in the cell editor, the formula bar or a text box as one undo step (a cell edit the workbook refuses, such as a Stop validation rule or a formula that doesn't parse, shows its usual message, closes without being entered and reopens with its text in the cell editor once that document is in front and editable again in the same session, `SheetApp::held_edits`); `setUser({id, name})` names the author of new comments, notes and replies (`Session::author`, never saved as a preference), `null` going back to the local name. A `view` or `comment` document is read-only through a host access state that is never written into the file (`DocState::access`, `crates/engine/src/doc_access.rs`, not sheet protection): `Session::execute` refuses every undoable command except zoom and opening a link, plus Undo, Redo, Cut, Repeat, Edit Cell, Save, Calculate, Custom Views, Record Actions, Run Macro and the Draw pens, with "This document is read-only." (also in `Session::commands`); `commit` refuses any content edit as a backstop; zoom, sheet switching and view changes stay out of the history and never make it dirty. The interface follows (`crates/ui-egui/src/read_only.rs`): no inline cell, formula-bar, text-box or sheet-tab editor opens (typing shows the read-only notice), the filter and validation drop-downs don't open, edit drags (fill handle, move, resize, freeze, objects) stop before moving, the editing ribbon tabs are greyed (hand-painted ribbon icons and labels of a disabled control fade to 0.3 opacity rather than egui's 0.5, which left them looking live, `widgets::ink`; this also applies to desktop wherever such a control is disabled), Home keeps Copy (when downloads are allowed) and Find & Select (Find, Go To, Go To Special; not Replace) and greys the rest item by item, and Review, View, the context menus, the title bar (Save, Undo, Redo, More) and File › Save are greyed item by item (`SheetApp::offers`); navigation, selection, Find, Go To, zoom and comment browsing stay. Such a document is never auto-saved and Ctrl+S only shows the notice (an access refusal isn't recorded as a failed save, so the status bar never shows "Save failed"); one opened read-only never becomes dirty, so `flush` resolves at once for it, while one downgraded with edits in hand stays dirty and `flush` hands it to `save` (reason `flush`) under rules 1–6 until it is saved or stopped by a conflict or a non-retryable failure (`dirty(false)` follows the save). A `flush()` the shell makes from inside one of this side's calls to it (its `dirty` handler flushes right after the downgrade's commit) is held while `HostDocs` is borrowed and runs before that frame ends (`FlushEntry`), instead of resolving without a save. `canDownload: false` refuses Copy, Cut, Save As, Save a Copy, Share, Export (PDF, CSV, HTML), Print and Print Preview with "Downloading, printing and copying are turned off for this document." and greys their menus. `preserveView` puts the newer version in the old one's tab, keeps the tab the user was on, and restores the active sheet by name with its selection and first visible cell when that sheet still exists (`crates/ui-egui/src/reload_view.rs`). Files dropped on the page still open as separate local workbooks, which doesn't change the host document. With a v2 shell the title bar's own Share button is hidden for its documents, the shell's Share being the only one (`DocumentHost::shares`, `SheetApp::host_shares`); local workbooks, a v1 shell, desktop and the free web build keep it.

- (web) Online documents through the office shell's `window.erpHost` v1 (`erpcons-office` `docs/erp-host.md`), checked once at start and never beside `?host=parent`: `open(doc)` opens an `.xlsx` as a new tab under its title (a second `open` of the same `docId` replaces that tab) and reports `opened(docId, ok, reason?)` once, refusing other formats, non-XLSX content, password-protected workbooks and the 10-document limit with the shell's intake key as the reason (`unsupported` for another format, non-XLSX content or a password; `parserFailed` for missing bytes, an unreadable file or the limit), the shell showing the sentence. The document counts as saved only on `saved`, as of the workbook that was sent (`Session::mark_saved`); `conflict` and a non-retryable `failed` stop its AutoSave and `flush` until a manual save succeeds (`failed` shows its message in the usual Save failed surface), `offline` and a retryable `failed` change nothing, and `acknowledged(docId, revision, version)` from the shell's own retry of such a save counts as `saved` for that revision (unknown documents, revisions never sent and ones older than the last acknowledged are ignored). `dirty(docId, bool)` follows each change of the unsaved state, `closed(docId)` the tab closing. The log privacy scan now also flags `doc`, `docId` and `bytes`.

In vi-VN, formulas keep English function names with `;` between arguments, `,` as the decimal point and `\` between array columns (`=SUM(1,5;2,25)`, `{1;3}`), and the formula bar redraws stored formulas in the chosen notation; typed numbers group with `.` (`1.234` is 1234, `1.234,5` is 1234.5), dates are day first (`19/10/2026`, `19/10` in the current year, `19-10-2026`), and `1.000.000 ₫` / `1.000.000đ` / `1.000.000 VND` become numbers formatted `#,##0 [$₫-42A]`; editing a cell shows its number or date in the same notation. The Accounting Number Format button applies the region's currency (₫ in vi-VN, `_-* #,##0 [$₫-42A]_-;…`) and its menu offers ₫. Files, `cell.set` without `region`, and stored formulas stay en-US; `TEXT()` stays en-US.
- Values are displayed in the regional format (`numfmt::format_value_in`, `display::*_in`, `Session::region`, which the app keeps in step): in vi-VN a format code's `.` and `,` show as `,` and `.` (`#,##0.00` shows `1.234,50`, General `1234,5`, `12,5%`, `1,23E+04`), the built-in short date (id 14, `m/d/yyyy`) and id 22 show day first (`19/10/2026`, `19/10/2026 13:30`) and `[$-F800]` long dates as `19 tháng 10 2026`, while explicit codes such as `mm/dd/yyyy` show as written; `mmm`/`mmmm`/`ddd`/`dddd` are `thg 10`/`tháng 10`/`T2`/`Thứ Hai` (CLDR `vi`). This covers the grid, the status bar sums, printing, print preview, Page Layout headers (`&D`) and PDF export (`region` param), charts (axes, data labels, categories), slicer tiles and filter lists (captions only: filter values and files stay en-US), Find (matches what is shown), the Number Format menu and Format Cells sample, and Ctrl+; / Ctrl+Shift+". Copied text follows the region and pasted text is read in it, like typing; CSV, web page export and XLSX stay en-US, as do `TEXT()`, `VALUE()`/`DATEVALUE()` and data returned to agents. In vi-VN the Currency and Accounting categories apply ₫ (`#,##0 [$₫-42A]`, the ₫ accounting code). Spanish keeps the en-US display.
- Opening a package (XLSX, XLSM, XLSB, ODS, also inside an encrypted workbook) checks what actually inflates, never trusting the sizes the zip headers declare: an entry inflating more than 200:1 once past 4 MiB, an entry or a package over its cap (already when a header declares it), or too many entries refuses the whole file, even when the part was optional, with "The file is too large or abnormally compressed, so it can't be opened." ("Tệp quá lớn hoặc bị nén bất thường nên không mở được."). The limits live in `crates/xlsx/src/limits.rs`: desktop keeps 512 MiB per entry, 1 GiB per package and 200,000 entries; the web build allows 256 MiB, 512 MiB and 50,000. Reading grows its buffer with `try_reserve`, so a failed allocation is that error rather than a crashed tab.
- `deny.toml`: a cargo-deny policy matching PdfCraft's (permissive licences only, crates.io plus the pinned craft-libs revision as the only sources, no wildcard requirements, RustSec advisories with a written reason for each ignore). Run with `cargo deny check`.
- Phones and tablets: below `NARROW_WIDTH` (600 points of window width; a tablet in portrait stays wide, `crates/ui-egui/src/narrow.rs`) the ribbon folds to its tab row once as the window crosses the breakpoint; the user can open it again and that holds until the window widens, which brings back the wide-window choice (also what `ui.json` saves meanwhile, `SheetApp::saved_ui`). The ribbon's tab row scrolls sideways (finger drag or wheel). Task panes and the PivotTable Fields pane float over the sheet when narrow instead of squeezing it. On a touch screen (`crates/ui-egui/src/touch.rs`, mouse and pen unchanged): a one-finger drag pans the sheet (with a short fling when animations are on; two fingers pinch-zoom), a tap selects, a double tap edits, a long press opens the cell or header menu, and a round handle on the selection's bottom-right corner drags out a range; a drag over a chart pans unless the chart is already selected. The fill handle and drag-to-move a selection stay mouse-only. When narrow, the title bar drops its optional controls lowest priority first (AutoSave label, theme switch, Comments, Home, undo list, the Share label, Redo; `crates/ui-egui/src/title_fit.rs`) and elides the workbook title into the room left; the status bar keeps, in order, the zoom buttons, Sum, the view buttons, Count, Average and the zoom slider as they fit, and leaves out a note on the left that would run into them; the PivotTable Fields pane gets a close button and stays closed until the active cell leaves that pivot.
- The "can't open" errors for a broken or refused file (not a valid zip package or spreadsheet, invalid XML, a missing workbook part, an ODS without sheets, a legacy binary that isn't a workbook, a damaged or unsupported encrypted file, a wrong password) show in the interface language: the message box matches them against the engine's English templates and translates the reason inside (`Language::tr_message`, `crates/ui-egui/src/i18n/messages.rs`), Vietnamese included; the engine, CLI and agents keep the English text. The PivotTable Fields pane wraps its Refresh / Calculated Field… / Report Layout row instead of clipping it, and Report Layout is a menu button so it can move to the next row (`pivot_pane.rs`).
- Large workbooks: web drafts are written with the fastest deflate (`drafts::draft_bytes` → `io::save_xlsx_fast`, `gridcraft_xlsx::Packing::Fast`): the same parts as Save, about two thirds larger, read back only by GridCraft, which halves the time a draft of a 45 MB workbook blocks the page (6.4 → 3.1 s natively); Save and Ctrl+S output is unchanged byte for byte, and drafts stay paced by 10× their last encoding time. `file.open` is journaled without the file it carries as `base64` (`cmd::journal_entry_params`), so an opened file no longer stays in the session journal (60 MB of text for that workbook) or in a recorded script; a dropped file's base64 is moved into the command instead of copied, and base64 decoding uses a lookup table (0.6 → 0.14 s for 45 MB).
- Documents closed in a session are kept (`crates/ui-egui/src/closed_docs.rs`: the ten most recent, 64 MiB at most, oldest dropped first, as the bytes a draft writes; never one opened with its password) and Reopen Closed Document (`file.reopenClosed`; the tab strip's right-click menu; File › Open; no shortcut) brings the last one back as a new tab under its name, unsaved if it was closed with Don't Save, within the 10-document limit. Ctrl+Shift+T stays AutoSum. The tab strip's menu also has Close Others and Close All, and closing the desktop window asks too: one dialog lists every unsaved document with Save All / Don't Save / Cancel (`close_many.rs`); Save All saves them one after another, each finishing before the next, and closes them once all are saved. On the web each browser save picker needs a click of its own, so after one has written its file the dialog stays up, that row reads “— Saved” (“— Đã lưu”), and the main button becomes Save “<next name>” (Lưu “…”) for the next picker; while a picker is open its row reads “— Saving…”, Save and Don't Save are disabled and Cancel stays enabled. Browsers without a save picker (Firefox, Safari) still download them all in one click. A cancelled or failed save, or Cancel while a picker is open, stops the rest and closes nothing; Cancel closes nothing; `app.quit` from the control channel still quits without asking. The status bar shows "Saving…" ("Đang lưu…") while a save is in flight (the web save picker; desktop writes are synchronous and show no in-flight state) and "Save failed" ("Lưu không thành công", reason on hover and click) until the next successful save or edit (`save_status.rs`); the failure message is translated. Vietnamese display only (files unchanged): PivotTable date-group labels show as `Quý 1`, `Thg1`, `4-Thg1` in vi-VN (`pivot_labels.rs`; the cells and saved XLSX keep `Qtr1`, `Jan`), time formats show AM/PM as SA/CH in vi-VN and typing SA/CH reads back as a time, the column width and row height tips use the decimal comma, and the Cell Styles gallery and the undo list show Vietnamese names (the engine and files keep the English ones).
- Macro-enabled workbooks keep their VBA project (both, mostly web). Save and Ctrl+S keep the kind the workbook was opened as: an `.xlsm` downloads (web) or is written (desktop) as `.xlsm` with `xl/vbaProject.bin` unchanged byte for byte (`save_as.rs`, `io::workbook_ext`; `file.saveBytes` already took `xlsm`/`xltm`, and `xlsx` still leaves the project out). Macros are still never run.
